# 真机采集清单（第二轮）

第一轮（`rec_20260418_191052`，296 s）证明了流水线能跑通，也暴露了瓶颈：
**只有一次录制、一种地面、一只机器人**，微调的样本外指标在 epoch 32 就平了，
而样本内还在降 —— 典型的数据不足。

这一轮要采两类东西，互不干扰，可以同一天做完：

| | 采什么 | 解决什么 | 要多久 |
|---|---|---|---|
| **A** | 多段无外力行走 | 数据量和多样性 → 压误报 | 4 段 × 3 分钟 |
| **B** | 配重吊拉 | **有力时的真标签** → 防止网络退化成"永远报零" | 8 段 × 40 秒 |

B 比 A 重要。现在真机只有单边监督（"力 = 0"），网络的最优解始终偏向少报；
B 是唯一能补上另一半的办法。

## A 组：多段无外力行走

全程**不用碰机器人**。目标是把第一轮缺的三个轴补上：

```
第一轮实测覆盖      走路 92 s   转向 81 s   侧移 6 s   倾角≥5° 只有 10 s
```

| 段 | 地面 | 内容 | 时长 |
|---|---|---|---|
| A1 | 和第一轮同一块地 | 1 档前后来回，杆从轻到满 | 3 min |
| A2 | **换一块地**（地毯 / 瓷砖 / 室外） | 同 A1 | 3 min |
| A3 | 任意 | **只推左横杆**，左右侧移来回（3 档） | 2 min |
| A4 | 任意 | 前进中频繁加减速、急停、突然转向 | 2 min |

A3 补侧移，A4 补姿态变化（加减速时机身会俯仰，正是现在最缺的倾角覆盖）。
A2 是四段里最值钱的 —— 换地面直接增加域的多样性。

## B 组：配重吊拉

### 物理设置

```
机器人 ──绳(水平, ≥3 m)──→ [定滑轮，固定在桌沿/支架] ──┐
                                                      │
                                                   配重 m kg
```

要点，每条都影响标签精度：

1. **绳子从机器人到滑轮这一段必须水平。** 不水平的话张力有竖直分量，和脚本里的
   水平假设对不上。滑轮装在和挂点差不多的高度。
2. **绳子要长，≥3 m。** 机器人被拉动 0.3 m 时方向只偏 6°，可以忽略；短绳不行。
3. **滑轮要带轴承。** 羊眼圈、挂钩的摩擦能吃掉 15–30%，而且方向相关。
4. **挂点要固定、要量。** 记下绳子系在机身的哪个位置（相对机身中心的 x/y/z，
   量到厘米就行）—— 这顺手把 `spec.TETHER_OFFSET_CONFIRMED` 也解决了。

### 先标滑轮效率（五分钟，但省掉系统性误差）

挂重之前，在绳子和机器人之间串一个**数显行李秤**，挂上配重静置，读数除以 `m × 9.807`
就是效率 η。四个方向各量一次（摩擦是方向相关的）。

没有行李秤就先按 1.0 跑，但要知道标签会**系统性偏高**，而且偏多少不知道。

### 配重档位

只有一个 2.5 kg 砝码的话，用**矿泉水瓶装水**补：1 L = 1.000 kg，很准。

| 配重 | 力 | 说明 |
|---|---|---|
| 0.5 kg | 4.9 N | 刚过 `FORCE_ACTIVE_N`，看低力段 |
| 1.0 kg | 9.8 N | |
| 2.0 kg | 19.6 N | |
| 2.5 kg | 24.5 N | 接近设计上限 30 N |

### 采集动作

**每一段都是：机器人站住（POLICY 模式、摇杆归中），把配重挂上去，静置 40 秒，取下。**

机器人会被拉着往前倾、甚至挪几步 —— 没关系，脚本按帧算方向。但它**不能走起来**
（摇杆别碰），否则配重在升降，张力就不是 m·g 了。

八段，覆盖四个方向 × 两个力档：

```
B1  front 1.0 kg      B5  front 2.5 kg
B2  back  1.0 kg      B6  back  2.5 kg
B3  left  1.0 kg      B7  left  2.5 kg
B4  right 1.0 kg      B8  right 2.5 kg
```

`front` = 绳子把机器人**往它自己的正前方拉**，其余同理。方向以**挂上去那一刻**
机器人的朝向为准。

**每段开始前记一下秒数**（从控制器启动算起，看 `tail -f log/bpx_dual_pad.log` 的时间戳，
或者干脆手机掐表）。后面 `--window` 要用。宁可窗口取窄一点 —— 只要配重完全悬空、
不晃的那一段。

python scripts/build_real_dataset.py \
    --rec logs/real_v6/rec_<A1> --rec logs/real_v6/rec_<A2> \

### B 组 → 带力标签的数据集

```bash
python scripts/build_weighted_dataset.py --efficiency <实测的η> \
    --rec logs/real_v6/rec_<B> --pull front --mass-kg 1.0 --window 10 50 \
    --rec logs/real_v6/rec_<B> --pull back  --mass-kg 1.0 --window 70 110 \
    ...
```

脚本会当场验四元数旋转（拿录制自带的 `projected_gravity_b` 对），并检查机器人
在窗口内确实站着没走。对不上会报错而不是出一份错标签。
